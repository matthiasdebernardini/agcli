Proposed changes (ranked, one commit each)

P0 — bugs in the hardening that just landed (fix first)

  • R1 — Short value flags are rejected as UNKNOWN_FLAG. extract_all_flag_names (src/cli.rs:2107) collects long flags and bracketed short booleans, but skips short value flags like [-n <count>] — so the framework rejects its own advertised usage, and renders the error as --n. Fix: collect -x from bracketed value-flag forms; format single-char unknowns with one dash. Repro: a CLI with usage "t log [-n <count>]" rejects t log -n 5.
  • R2 — Out-of-range handler exit code panics outside the panic guard. normalize_exit_code's debug_assert (src/envelope.rs:121) fires in the framework's post-handler path, after catch_unwind — producing zero JSON on stdout and exit 101, exactly what the guard exists to prevent. Fix: clamp/validate inside CommandOutput::exit_code / CommandError::exit_code (inside the guarded handler context) and never assert in the post-handler path.

P1 — remaining silent-fail / pedagogy gaps (re-verified open at HEAD)

  • R3 — Arity validation: reject extra positionals. calc add 1 2 3 exits 0 and drops the third arg. For a mutating CLI (tool delete <id> <oops>) this is dangerous. Count <...> placeholders in the leaf usage string (the scanner already exists for next_action_from_usage); when extra args are present and usage lacks ..., return EXTRA_ARG at USAGE exit with the unexpected token named. Opt-out for variadic commands.
  • R4 — Did-you-mean for typo'd flags must include reserved flags. --selct gets the generic reserved-flag list but no "did you mean --select" nudge — candidates (src/cli.rs:1402) come from declared flags only. ~3-line fix; also sort candidates before tie-break so the suggestion is deterministic (it's currently HashSet-ordered).
  • R5 — Honor --select/--quiet/--compact on root/help/version paths. The root tree advertises these on "every command", but root/help/version bypass the projection block. calc --quiet still emits next_actions. Factor the projection into a helper applied on all paths — the root tree of a large CLI is precisely where agents want --select=commands.
  • R6 — Alias bare version positional to the --version envelope (like the existing help alias), unless the user defined a version command.
  • R7 — --dry-run=false currently enables the flag (presence-tested). Treat =false/=0 as off for reserved booleans, or reject the =value form with a teaching error.
  • R8 — Non-finite float guard. calc add 1e308 1e308 → ok:true, result:null (serde_json folds inf/NaN to null). Make arg_parse::<f64> reject non-finite parses as INVALID_ARG (Rust's FromStr accepts "inf"/"NaN"), and fix the calc example to guard overflow. Closes the last observed ok-true-with-corrupt-result path.

P2 — contract export + regression resistance

  • R9 — Runtime-discoverable error-code dictionary. The exit_codes dictionary just landed in root help; add the conventional error codes (MISSING_ARG, INVALID_ARG, UNKNOWN_FLAG, DRY_RUN_UNSUPPORTED, HANDLER_PANIC, …) alongside it so agents can build retry/branch policy from one root call.
  • R10 — Golden-envelope snapshot tests. ~15 canonical invocations run under SOURCE_DATE_EPOCH=0 asserting exact output bytes (success, each error code, select warnings, help, version, root). The envelope is hand-serialized; nothing currently pins the bytes. Doubles as a living spec.
  • R11 — cli.audit() checks the usage-string/parser coupling. Usage strings ARE the flag schema; a malformed bracket silently changes parsing today. Add findings: unbalanced brackets, usage/program mismatch, reserved flag redeclared.
  • R12 — SOURCE_DATE_EPOCH edge cases + tests. Clamp huge values to 9999-12-31 (current output of year-584-billion timestamps can't round-trip through the crate's own parser); per the reproducible-builds spec, malformed values should clamp to 0 rather than silently falling back to the wall clock. The env-var path currently has zero test coverage.
